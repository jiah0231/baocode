# Chrome 连接面板（1.8.0+28）

此面板连接用户正在使用的 Chrome，通过原有 BaoCode 扩展显示和操作已共享的标签页。它不是独立浏览器内核，不导出或复制 Chrome 的登录资料，也不需要新增扩展权限。Chrome 仍须运行。

## 使用

- 地址栏支持 HTTP/HTTPS，提供前进、后退、刷新、新建和关闭标签页。
- 标签选择绑定具体浏览器连接与标签 ID。Agent 操作别的页面不会改变右栏选择；连接丢失不会自动改用另一个 Chrome。 同一会话的 Agent 连接在首次使用后固定，随后切换面板不会改写它。原连接断开时，可先选择目标浏览器，再明确点击“重新连接此会话”。旧会话调用将作废，新的调用才可使用所选连接；这不会自动恢复暂停中的 Agent。
- 多个浏览器连接使用浏览器名称和连接编号区分，编号不是 Chrome 个人资料名称。新建页会使用所选连接的 BaoCode 标签组，不保证位于所选标签的同一窗口。
- 每次启动 BaoCode 都暂停 Agent 的浏览器观察和操作。只有本次明确点击“继续”才恢复；不会读取旧的“已恢复”标记来自动放行。
- “我来接管”立即撤销 Agent 的后续浏览器请求，连同截图、DOM 和网络读取一起暂停。已经发出的请求可能完成，已经进入会话上下文的信息不会被撤回。
- 人工面板仍可使用。切换时需要有界的录制清理；清理失败则保持暂停并显示错误，点击“继续”会重试，不会无限等待离线 Chrome。
- 取消 Chrome 的调试提示后，不会因缩放、切换侧栏或重开会话而自动连接；必须明确选择页面或点击重新连接。
- 原生对话框、权限提示及下载请在 Chrome 中处理。无法确认产生时间的弹窗和下载通知不会被当作接管后的新历史补录。

## 数据边界

接管会停止新的 Agent 录制，丢弃旧录制代次和不能证明新鲜度的延迟事件。恢复后只为明确使用的页面重新建立录制，不枚举和补录人工阶段的浏览历史。原有已保存历史及 Chrome 的控制台、历史记录不被清除。持久化控制标记只包含暂停状态，不包含页面、账户或登录数据。

此功能没有新增 Cookie 或凭据导出接口。它也不改变原有实时网络诊断功能的整体数据范围；不要把面板升级理解成所有既有诊断输出都经过完整凭据脱敏。

## 回归验证

无需个人 Chrome 账户的自动化测试：

```
node --test test/browser/browser_recorder_script_test.mjs
flutter test test/browser/browser_panel_controller_test.dart test/browser/browser_toolbar_test.dart test/browser/browser_frame_flow_test.dart test/browser/browser_agent_control_test.dart test/browser/browser_mirror_test.dart
```

测试使用隔离的数据目录及本机合成协议端点，覆盖连接身份、导航竞争、全局请求门控、接管后的延迟结果、重新启动、录制代次、帧合并、隐藏暂停和取消连接后的输入清理。Windows 工作流先运行这些检查，再执行现有回归、原生库校验、构建和 +27 → +28 安装升级测试。

另有可选的 [独立 Chrome for Testing CDP 检查](../test/browser/fixtures/REAL_CHROME_SMOKE.md)，两个 Windows 工作流会明确启用。它使用临时浏览器资料、本地测试页面和真实 CDP 回应，验证接管清理、恢复以及人工阶段数据不会补录。它替代了扩展/原生消息宿主的传输，不能证明真实扩展、共享权限或宿主安装流程端到端通过。

用户实际 Chrome、Windows 输入法候选窗位置、各站点弹窗与视频表现仍需设备验收。面板保留 CDP 图像传输方式，不声称等同原生嵌入浏览器或完全同步个人资料。

现有依赖真实 Chrome 的手工 `*_live_test.dart` 脚本尚未全部迁移到本版启动暂停和不自动接受对话框的行为；普通 CI 不启用它们。运行真实设备验收前须显式恢复 Agent，并更新旧的自动弹窗/被动历史断言，不能以本版合成测试通过代替真实设备验收。
